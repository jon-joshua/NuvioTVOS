# Dead Code Audit — NuvioTVOS

Date: 2026-09-03
Branch audited: `chore/search-tidy` at `9a3a568`
Scope: read-only audit. No changes were made.

"Dead code" here covers three layers, in decreasing size:

1. Repo-level weight that the tvOS build never touches (~530 MB of tracked build output plus an unused Kotlin app).
2. Swift compiled into the tvOS target that nothing reaches.
3. Compose/Kotlin-era patterns reimplemented in Swift where tvOS 18 already provides the behaviour (~1,900–2,600 lines).

## Suggested order

1. **Zero risk:** delete `artifacts/`, `build/`, `Vendor/__pycache__`, and the nine orphan test files (or add them to the project if any are worth reviving). Decide whether `composeApp/`, `iosApp/`, and the Gradle files stay as references or move to a separate archive branch.
2. **Trivial:** dead files, `DomainModels` stubs, uncalled functions, compatibility aliases, unused `SettingsKey` constants. Wrap `ContinueWatchingTestData` in `#if DEBUG`.
3. **Low-risk table rows:** availability shims (§3 #10), `trimmedNonEmpty` (#13), Keychain store (#3), search view-model dedupe (#4), regex helper (#9), decoder defaults (#5), image caches (#6), `TVCollectionFolderRow` (#7), polling → push (#8), date locale, `print` → `Logger`.
4. **Last, behind a flag, one destination at a time:** `NavigationStack` router (#2) and `@Observable` migration (#11). Both touch tvOS focus behaviour.

## Method notes

- Symbol scans were grep-based word counts across `tvosApp/**/*.swift`; a name counted as dead only when it appeared nowhere outside its own declaration line(s). False negatives are possible for names that collide with common words (e.g. `load`), so the function list is a floor, not a ceiling.
- Project membership was checked by basename against `tvosApp/NuvioTV.xcodeproj/project.pbxproj` (explicit `PBXBuildFile` entries, no synchronized groups).
- Section 3 findings were verified by reading the cited line ranges.
